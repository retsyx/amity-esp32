# Control-surface evidence

The current contract is [baseline UI](../../amity-octopus-consortium/20-user-interface.md) and [original-controller policy](../../amity-octopus-consortium/21-original-controller-policy.md). Only the original main hosts UI, home integrations and the sole physical remote. Members execute authenticated guarded semantic work and publish observations; they have no input gateway or hosted UI.

`SystemControl`/`HubService`/`LiveSystem` retain scoped names, current binding evidence, resource planning and first-frame fences behind the baseline activity adapter. Save and Scan never start playback. Explicit Start uses stable ActivityId, current revisions/context, bounded stop barriers and normal planner admission. External slots and per-ActivityId aliases remain stable. Portable main recovery imports no authority, trust, pairing or old executable work.

The merge of `main`'s remote behavior retains independent logical keys through both input paths. `SystemControl` stores a separate hold token per key; `LiveSystem` likewise tracks each local compatibility key independently. A keyed up releases only that token. The emitting owner admits CEC frames immediately and repeats each still-held key after its own successful completion. Volume Up, Right and Right-up therefore leave Volume Up repeating, including when the first attempt has not yet completed. Failed-key metadata remains consumed until its matching up, so unchanged physical down reports cannot restart it.

The original controller uses the shared `RemoteInputController` for Siri-only fixed Power+Select/Up/Right/Down/Left activity macros (0–4, or 5–9 after a 500 ms selector hold), independent releases and `wait_for_release`. Accepted explicit activity/configuration selections publish a separate revision to arm the release guard, including a same-activity selection; repair via long Power does not. Rejected actions retain unrelated held keys. Startup and accepted selections suppress fresh input until all physical buttons are up or the one-second fallback expires; a blocked old hold never replays.

Cross-screen selection hands one typed selection intent to the owner and returns admission without waiting for a CEC ACK or remote response. The owner advances only the necessary stop/route fences incrementally, retaining exact original sessions and configuration revisions so an intervening change cannot replay the selector. IPC freshness is checked before admission and adds no deadline to an accepted activity's CEC execution. This is transition state rather than an outgoing CEC queue. Input routing uses the admitted session projection, which becomes available when route authority is installed; committed-session/outcome publication does not gate keys on setup ACKs. Expired member identities similarly use asynchronous two-poll validation; positive requests reject busy while validation is pending, without retaining a frame or ordinary request for later capacity admission. `system_remote_control_test.sh` covers pending-completion key overlap, keyed release under a full ordinary IPC queue, nonblocking screen selection, activity-selection revisions and repair behavior; `ble_test.sh` covers the shared macro and release-guard state machine.
