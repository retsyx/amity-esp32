# Remaining implementation work

Recorded 20 October 2026 after a read-only audit of firmware 0.1.60, then updated for the original-controller requirements and 0.1.62 source cleanup. Open checkboxes below require evidence. Obsolete member-input, controller-transfer and replacement-wizard requirements are removed from the current contracts. Passing the existing tests does not close these gaps; record the implementation and relevant validation evidence before checking an item off.

This is the software and release-process backlog. Physical qualification remains tracked in [validation and release gates](15-validation-and-release-gates.md), [engineering gates](17-decisions-and-open-questions.md), and the [implementation status](../IMPLEMENTATION_STATUS.json).

The current CEC admission amendment is eight normal messages plus one release-only overflow message per wire, including active work. A release may become message nine; further releases at nine are dropped without executor admission retry. Necessary bounded task-to-task communication queues remain permitted; they must not become outgoing-message or retry backlogs.

**21 October 2026 preservation rule:** original Amity algorithms and functionality at `d50af8026938797fc0820d0107f4c4e064c2d2bc` remain authoritative unless the user explicitly asks for a change. The consortium adds ownership and transport around those algorithms. Every item below must preserve existing behavior and approved user amendments; a backlog proposal is not authorization to redesign the original algorithms. See [AGENTS.md](../AGENTS.md) and the [normative amendment](21-original-controller-policy.md#original-algorithms-and-functionality-amendment--21-october-2026).

This historical firmware used commands-first pacing, superseded by current `main`: keys complete independently and new commands submit immediately while ACKs remain pending, with one wire attempt per key press. Failed TX ends that key; later up is a no-op. Release is implicit at recipient stream end only when all keys there cease being pressed, including last-key failure. Its sole per-wire FIFO admits eight normal messages plus one release in slot nine; further releases at nine drop without later admission retry. Necessary bounded IPC remains handoff only. Exact current-state classification makes failed-key up harmless under IPC pressure without new queues or expiring outcome/history guesses. Initial freshness, current authority, safe binding fences and original audio-query timing remain distinct. ## Supported limits and deferred scope

The current profile permits **three active devices**, one remote on the original controller, no hosted UI/integrations on added devices, and one primary Matter/HomeKit zone. These are explicit limits, not unchecked implementation tasks. Expanding toward eight active devices would require transport, socket, memory, storage, cohort-update and backup capacity work followed by qualification.

Controller promotion/handover, election, standby-controller or automatic failover are **outside scope and not planned work**. If the main is absent, headless members preserve isolation, release/expire exact held work and wait for that same main. Historical transfer state is passive recovery data only. ARC/eARC, built-in TV applications, direct peer actuation, additional external integration zones, transparent fabric/bond migration, Wi-Fi mesh and network video remain [separately deferred](17-decisions-and-open-questions.md). They are not required to close this checklist. Restart resumption continues to require fresh explicit intent.
